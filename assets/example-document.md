# AI项目文档交付规范

面向跨角色协作的双模式文档示例

**核心目标：**让决策者先看懂结论，让执行者迅速找到动作；同一份内容能分别用于**屏幕阅读**和正式交付。

## 读者与使用边界

本文说明如何整理一个 AI 项目的需求和交付材料。它是一份**排版与信息组织示例**，不代表某个真实项目的完成记录。

| 信息 | 内容 |
| --- | --- |
| 决策者 | 优先看到项目目标、投入边界和验收标准 |
| 执行者 | 优先看到任务顺序、责任和输出物 |
| 使用者 | 优先看到使用场景与异常反馈方式 |

## 内容组织步骤

1. **写出读者要完成的判断** — 一句话说明本文件帮助谁决定什么
2. **展开必要证据** — 用普通段落解释因果、条件和限制
3. **安排信息容器** — 用表格比较字段，用步骤表达依赖
4. **验证下一步行动** — 每个关键要求都能对应责任和验收证据

> **设计提醒**  灰色卡片仅承载具有明确边界的信息，**普通解释仍保持白底**。正式 Word 中可把这类说明改成简短的加粗引导句。

## 不同格式的交付映射

| 媒介 | 适合内容 | 必须验证 |
| --- | --- | --- |
| Word / PDF | 正式报告与提交文件 | 分页、字体和表格断行 |
| Markdown | 知识库与团队协作 | 标题结构与粘贴兼容 |
| HTML | 视觉预览与练习 | 响应式布局与键盘操作 |

同一块信息在不同媒介下可以改变表现形式，但不能改变含义。**视觉一致不等于逐像素相同。**

## 验收与交互示例

- 首次阅读能够快速说出文件的目的
- 每张表都能回答一个具体比较问题
- 跨页后没有孤立标题或缺失汉字
- 输出文件与源内容一致，并标明未完成的检查

如果一份文档显得拥挤，你会先检查哪一个问题？
- A. 是否**每一句**都被加粗或装进卡片？
- B. 是否标题太多、段落之间缺少关联？
- C. 是否表格太宽、列字段无法直接比较？
